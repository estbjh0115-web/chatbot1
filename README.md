# PDF 질의응답 챗봇 — 1~4단계 + 오류 대처 통합본

한화시스템 교육 슬라이드의 1~4단계 실습 기능과 오류 대처 항목을 하나의 Streamlit 앱에 통합했습니다.

## 이미지·표·그래프 자동 분석 (선택 기능)

**기존 K-EXAONE 2.5는 텍스트 전용입니다.** 아래 기능은 "그림·표 보강" 메뉴에서 사용자가 버튼을 눌렀을 때만 동작합니다.

- **로컬 OCR**: Tesseract + PyMuPDF로 스캔 페이지의 한글·영어 글자를 인식합니다. 기본 EXAONE 키 또는 별도 API 호출이 필요하지 않습니다. 숫자·축·단위 오인식은 직접 확인하세요.
- **PDF 표 추출**: PyMuPDF로 텍스트/벡터 기반 표의 행·열을 추출합니다. 이미지로 된 표는 일부 또는 전부 추출되지 않을 수 있습니다.
- **비전 AI 분석**: 선택한 PDF 페이지 이미지 1개를 Google Gemini API로 전송해 표·그래프·도식을 해석하고, 보강 초안을 만듭니다. **별도 Gemini API 키와 명시적 전송 동의**가 필요하며 요청당 비용 또는 이용 제한이 발생할 수 있습니다.
- **원본 검증과 수동 승인**: 자동 결과는 **검토용 초안**에만 표시됩니다. 원본과 비교해 잘못된 수치·단위를 수정한 뒤, `검토한 내용 저장 · EXAONE 검색 반영` 버튼을 누르면 기존 PDF 원본을 변경하지 않고 검색용 보강 자료에 추가합니다.
- **시각자료 후보 탐지**: 이미지 수·벡터 선·원문 글자 수로 검토가 필요한 페이지를 표시합니다. 이미지의 의미를 자동 확정하는 기능은 아닙니다.

### Codespaces OCR 설치 (최초 1회)

```bash
sudo apt-get update
sudo apt-get install -y tesseract-ocr tesseract-ocr-kor tesseract-ocr-eng
tesseract --list-langs
python -m pip install -r requirements.txt
```

언어 목록에 `kor`와 `eng`가 표시되어야 합니다. 컨테이너를 새로 만들면 시스템 패키지 설치를 다시 해야 할 수 있습니다.

### Gemini 이미지 분석 준비

Google AI Studio에서 Gemini API 키를 발급한 뒤, 앱의 **그림·표 보강 → 그래프·이미지 AI 분석**에서 비밀번호 입력란에 입력하세요. 공유 PC에서는 키를 저장하지 마세요. Codespaces Secret 이름을 `GEMINI_API_KEY`로 설정하는 방법도 사용할 수 있습니다.

**주의:** PDF에 기밀·개인정보·제3자의 비공개 자료가 있을 경우 외부 비전 API로 전송하지 마세요. AI가 판독한 수치나 그래프는 검증이 필요합니다. 이미지 OCR이 가능하더라도 완벽한 데이터 추출을 보장하지 않습니다.

## 주요 기능

| 구분 | 구현 | 비고 |
|---|---|---|
| 1단계 | 복수 PDF 업로드, PyMuPDF 페이지별 텍스트 추출, EXAONE 질의응답, `[파일명 p.번호]` 출처, 파일·페이지·글자 수 | PDF에서 찾지 못하면 `문서에서 찾지 못했다.` |
| 2단계 | 페이지별 원문/보강 글자 수, 원문 120자 미만 필터, 오름차순, 원본 페이지 이미지 | 그림/도표 여부는 사람이 확인 |
| 3단계 | `.txt`·`.md` 보강 파일 업로드, `[파일명 p.번호]` 구간 연결, 미연결 경고, 보강 글자 수/검색 반영 | 원본 PDF 자체는 수정하지 않음 |
| 4단계 | `id,질문` CSV 업로드 → 문항별 AI 답변 → `id,질문,답변` UTF-8-SIG CSV 다운로드 | 최대 100문항, 오류행도 기록 |
| 오류 대처 | 설치 진단, API 연결 버튼, 400·401·403·429·5xx 안내, 빈 답변/`max_tokens` 조절, 동일 오류 3회 연속 시 추가 일괄 API 호출 중단 | 키/원문을 오류 문구에 노출하지 않도록 처리 |
| 부가기능 | 수동 이미지 설명 보강, 문제 출제/채점, 텍스트 직접 입력 일괄 답변 | 모델 생성물은 원본 검수 권장 |

EXAONE 공식 문서: https://docs.exaone.ai/ko/docs/k-exaone-2.5

## 설치: GitHub Codespaces

1. 이 ZIP의 **압축을 푼 내용** 전체를 새 GitHub **Private** 저장소의 최상위에 올리세요. `.streamlit`, `.devcontainer`, `.github` 등 숨김 폴더도 포함합니다.
2. 저장소에서 **Code → Codespaces → Create codespace on main**을 선택합니다.
3. `.devcontainer/devcontainer.json`의 `postCreateCommand`가 의존성을 자동 설치하도록 지정되어 있습니다. 설치가 실패했거나 프로젝트를 덮어썼다면 터미널에서 재실행합니다.

   ```bash
   python -m pip install -r requirements.txt
   ```
4. 실행 전 Codespaces 터미널에서 아래 두 명령으로 설치와 실제 서버 응답을 검증합니다.

   ```bash
   python verify_install.py --smoke-server
   python -m unittest discover -s tests -v
   ```

   - `verify_install.py --smoke-server`는 잠깐 Streamlit 서버를 실행해 `/_stcore/health` HTTP 200을 확인한 뒤 종료합니다.
   - `tests`는 로컬 모의 API로 1~4단계, 3회 연속 오류 차단, 401·403·429·5xx, 빈 답변 등을 자동 검증합니다.
5. 웹앱을 실행합니다.

   ```bash
   streamlit run app.py --server.address 0.0.0.0 --server.port 8501
   ```
6. Ports 탭의 **8501**을 열어 화면을 확인합니다. 포트 가시성은 **Private**으로 유지하세요.
7. 사이드바의 API 키 입력칸에 키를 넣고 **API 연결 테스트**를 클릭합니다. 이 버튼은 **실제 EXAONE API를 1회 호출**합니다. 연결 성공이면 PDF 업로드/질의를 진행하세요.

**키 관리:** API 키를 GitHub 코드·README·채팅에 붙여넣지 마세요. Codespaces Secrets로 `EXAONE_API_KEY`를 설정해도 앱이 읽을 수 있습니다. 키는 앱 비밀번호 입력란에서만 마스킹해서 보입니다. API 연결 테스트는 문서 내용을 보내지 않지만 API 이용량이 발생할 수 있습니다.

### 실 API 확인 (선택)

Codespaces Secrets에서 `EXAONE_API_KEY`가 설정된 경우 다음을 실행할 수 있습니다.

```bash
python verify_install.py --live
```

실제 연결 성공 여부만 표시하고 API 키·응답 본문은 기록하지 않습니다. 실제 API 사용량이 발생할 수 있습니다. 비밀 환경변수가 없으면 앱의 **API 연결 테스트** 버튼을 사용하세요.

## 보강 파일 형식

PDF의 실제 이름이 `학습자료.pdf`라면 다음과 같은 `.txt` 또는 `.md` 파일을 업로드합니다.

```text
[학습자료.pdf p.2]
이미지의 그래프에서 A는 35%, B는 65%이다.

[학습자료.pdf p.5]
표 2의 합계는 120건이다.
```

제목 줄은 반드시 `[파일명 p.번호]` 형식을 사용합니다. 존재하지 않는 파일/페이지, 해석할 수 없는 구간은 페이지에 임의 연결하지 않고 경고를 표시합니다.

## 일괄 질문 CSV

업로드 파일의 첫 행은 **반드시** `id,질문`입니다. UTF-8 또는 UTF-8-SIG를 사용하세요.

```csv
id,질문
001,PDF에서 설명하는 핵심 용어는 무엇인가요?
002,표에 있는 주요 수치는 무엇인가요?
003,문서의 조건을 설명해 주세요.
```

앱 사이드바에서 PDF와 CSV를 올리고 **일괄 질문 실행**을 클릭합니다. 결과 파일의 열은 반드시 `id,질문,답변`으로 만들어집니다. 인코딩은 UTF-8-SIG이며, 한글/선행 0 확인을 위해 엑셀에서는 CSV 가져오기를 사용해 ID 열 형식을 `텍스트`로 지정하는 것을 권장합니다.

질문별 오류가 발생해도 일반적으로 다음 질문을 이어서 처리합니다. **동일 오류가 3번 연속 발생하면** API를 계속 호출해 비용을 쓰지 않도록 후속 요청을 중단하고 남은 행을 중단 사유로 채웁니다. 중요한 문항은 답변 근거를 원문 PDF와 대조해 주세요.

## 오류 진단

| 현상 | 확인할 조치 |
|---|---|
| `ModuleNotFoundError` | `python -m pip install -r requirements.txt` 실행 후 앱 재시작. `python verify_install.py`에서 패키지 확인 |
| HTTP 401/403 | 키 재입력 및 계정·모델 접근 권한 확인. 키를 오류 보고서에 붙이지 않음 |
| HTTP 429 | 계정 요청 한도·이용량 확인, 잠시 요청 중단 |
| HTTP 500/502/503/504, 네트워크 | 인터넷/서버 상태 확인 후 재시도 |
| 빈 답변·잘린 답변 | 앱 사이드바 **답변 최대 토큰 수**를 올리고 질문 범위 축소 (추론 토큰도 포함) |
| 3회 반복 오류로 중단 | 코드의 원시 예외 메시지 대신 화면의 오류 유형과 행 번호만 운영자에게 전달 |
| 보강 내용 연결 안 됨 | `[업로드한실제파일.pdf p.번호]`의 파일명/페이지 번호 확인 |
| 글자 수 0인 페이지 | 원본 이미지 미리보기 후 `.txt`/`.md`로 내용을 보강 |

## 자동 검증과 제한

- `python -m unittest discover -s tests -v`는 실제 PDF 바이트와 가짜 EXAONE HTTP 응답을 이용한 단위/통합 테스트입니다.
- GitHub Actions에 `.github/workflows/tests.yml`을 추가했습니다. 저장소에 파일을 올리면 GitHub가 의존성 설치, Python 문법 검사, 28개 테스트, Streamlit HTTP 헬스체크를 수행하도록 설계되어 있습니다. **Actions 실제 실행 여부는 저장소에 올린 뒤 확인해야 합니다.**
- 현재 파일 제공 환경에서는 `streamlit` 패키지가 설치되지 않았고 패키지 서버 연결이 차단되어, **실제 Codespaces 브라우저 구동/EXAONE API 호출은 직접 검증하지 못했습니다.** 자가 검증 스크립트 및 연결 테스트 버튼을 넣어 사용자의 Codespaces에서 바로 확인할 수 있도록 했습니다.
- EXAONE은 텍스트 전용 모델이므로 PDF 그림은 자동 해석하지 않습니다. 페이지 이미지로 확인 후 보강 문서에 텍스트로 입력해야 합니다.
- PDF/보강 문서에 기밀이나 개인정보가 포함될 수 있습니다. 관련 문단이 외부 EXAONE API로 전송되므로 승인된 자료만 업로드하세요.

전체 검증 결과는 [VERIFICATION_REPORT.md](VERIFICATION_REPORT.md) 참고.
